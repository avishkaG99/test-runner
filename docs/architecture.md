# Architecture

## Stack

| Concern | Choice |
|---|---|
| Build | Vite 8, TypeScript strict |
| UI | React 19, Tailwind v4 |
| Routing | TanStack Router, file-based routes |
| Data | TanStack Query over Axios service modules |
| Mock backend | MSW handlers on in-page fetch/XHR interceptors |
| Tests | Playwright (Chromium, Firefox, WebKit) |

### Why a SPA and not Next.js

There is no backend to serve, so SSR, SEO, and API routes buy nothing here. Server components and hydration would add timing subtleties that work *against* a deterministic test target. A client-only SPA keeps all state inspectable and every transition observable in the DOM.

## Folder layering

```
src/
  routes/       TanStack file routes — thin wiring only
  features/     One folder per product area; the screens live here
  components/   Shared UI: ui/ primitives, layout/ chrome
  hooks/        Reusable hooks; hooks/api/ holds Query hooks
  contexts/     Cross-cutting React context (auth)
  lib/          Utilities, auth helpers, Axios client
  lib/api/services/   Plain async functions per domain
  mocks/        Handlers, seed data, in-memory database
  types/ enums/ Shared types and constants
```

The mental model: **a route file is the address and doorbell; the feature file is the actual room.** Both are often called `index.tsx`, and they do different jobs.

### Import direction

Imports point inward, never back out:

```
routes    →  features, components, hooks, contexts, lib, store, types
features  →  components, hooks, contexts, lib, types
components→  hooks, contexts, lib, types
lib       →  types, other lib
types     →  nothing application-specific
```

Hard rules:

- `features/` must never import from `routes/`
- `lib/` must never import from `components/`, `features/`, or route files
- `types/` and `enums/` import nothing app-specific — no React, no store
- Query hooks call service modules; they never issue raw `fetch` or one-off Axios calls

Use the `@/` alias rather than deep relative paths.

## Route guards

Auth is checked once, on the `_authenticated` layout's `beforeLoad`. Every child route inherits it, so a new protected page needs no guard code of its own.

Role checks stack on top: [`/admin`](./features/admin.md) adds its own `beforeLoad` for the admin role, running after the sign-in check has already passed.

The router's context is seeded from `localStorage` at creation time, so the first `beforeLoad` on a cold page load sees the real session rather than `undefined`. The live context from `RouterProvider` supersedes it once React mounts.

### Generated route tree

`src/routeTree.gen.ts` is generated by the TanStack Router Vite plugin and **is committed**, so a fresh clone typechecks before the first dev run. It regenerates on dev and build.

## The mock backend

There is no server. MSW handlers run **in-page via fetch and XHR interceptors** — not a service worker.

That is a deliberate departure from MSW's default browser setup, and it is worth knowing why.

MSW's service worker calls `location.reload()` when it finds an existing registration but `navigator.serviceWorker.controller === null`, treating that as a worker that has lost control and needs a reload to recover. Firefox reports a null controller on **every fresh document load** until the worker claims the page. Playwright drives full page loads constantly, so that recovery path fired on every navigation and turned the app into an infinite reload loop — pages rendered blank and the suite failed.

Intercepting fetch and XHR directly removes the service worker entirely:

- No registration to go stale, so no reload logic
- Requests are mocked from the first tick, with no window where they 404
- No `mockServiceWorker.js` to keep in `public/`

The tradeoff: requests made outside the page's JS context are not intercepted. Nothing in this app does that, and the [iframe](./features/ui-playground.md#appendix--test-surface) deliberately loads from a blob URL to stay off the network entirely.

Handlers live in [`src/mocks/handlers.ts`](../src/mocks/handlers.ts) and are unchanged from standard MSW — only the transport differs. See [Mock API](./mock-api.md).

## State and persistence

| What | Where |
|---|---|
| Session | `localStorage`: `tta.token`, `tta.user` |
| Product data | `localStorage`: `tta.products` |
| Preferences | `localStorage`: `tta.theme`, `tta.latency`, `tta.flakyMode` |
| Server cache | TanStack Query, in memory |

Query retries are **disabled app-wide**. Retrying would mask the deliberate error states this app exists to expose.

## Adding a feature

1. Build the screen under `src/features/<name>/`
2. Export it from `src/features/<name>/index.tsx`
3. Add a thin route at `src/routes/_authenticated/<name>/index.tsx`
4. Add a nav entry in [`authenticated-layout.tsx`](../src/components/layout/authenticated-layout.tsx)
5. Give every interactive element a `data-testid` (see [conventions](./testing-guide.md#selectors))
6. Document it under `docs/features/` and add it to [test-map.json](../test-map.json)
7. Run dev or build so the route tree regenerates
